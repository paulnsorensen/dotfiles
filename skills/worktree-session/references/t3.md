# T3 routing

Read the live tool contracts before constructing calls.
Use the callable tool name, including its harness prefix.
A directory change does not update the T3 thread binding.

## Inspect

Call `t3_worktree_status` for the current binding.
Use `t3_worktree_list` to locate an existing checkout.
If catalog discovery omits T3 tools, make one bounded direct `orchestrator_capabilities` attempt.
A failed lookup does not authorize a CLI or permission bypass.
Use the supported ACP transport fallback only when the environment advertises it.

## Choose by requested ownership

| Request | Mechanism | Completion evidence |
| --- | --- | --- |
| Child task in a new checkout | `delegate_task` with `isolation:"worktree"` | Child reports its checkout, branch, starting base commit, and write access |
| Explicit new or separate conversation | `t3_thread_launch` with an explicit `workspaceStrategy` | Destination conversation confirms its binding and access |
| Move the calling root thread | `t3_worktree_handoff` after status confirms it is unattached | Continuation verifies the new session |
| Current thread already bound to the requested checkout | Keep that binding | Verify its branch and access |
| Current thread bound elsewhere | No second handoff | Report the limitation without creating another conversation |

## Child work

Discover the provider, model, and options with `orchestrator_capabilities`.
Follow the live delegation contract for model selection and option inheritance.
Worktree isolation starts from the parent's local commit.
Before delegation, compare that commit with the resolved requested base commit.
Report blocked if they differ, including independent work that requires a different remote-default commit.
Do not launch a substitute conversation or change the parent's branch to bypass this mismatch.
Require the child's destination verification to confirm the starting base commit.
It does not copy uncommitted changes.
Retain the returned `taskId`.
Use `task_status` for necessary status checks.
Do not send another review round to `childThreadId`; delegate a new task instead.

The child tool has no existing-worktree selector.
Do not substitute a fresh child checkout for a requested dirty checkout.
Report the limitation when child work requires that existing checkout.
Ask about another conversation only when the user needs to choose that different ownership model.

## Explicit conversations

Use `workspaceStrategy.type:"existing_worktree"` for a requested existing checkout.
Supply its inspected `worktreePath` and branch.
This preserves its uncommitted changes.

For a new checkout, use `workspaceStrategy.type:"worktree"`.
Supply `baseRef` and the intended branch.
Set `startFromOrigin:false` for local dependent work.
Set `startFromOrigin:true` only when the intended base comes from the remote.
Omitting `workspaceStrategy` selects the project root, not the caller's checkout.

Retain `threadId`.
Inspect preparation and destination evidence with the thread read or wait tools.
Before retrying a failed or lost launch response, inspect the thread list.
The launch has no idempotency key.

## Move the calling thread

`t3_worktree_handoff` cannot move an already-bound thread.
It creates a new checkout, not an existing-checkout selection.
Set `baseRef` and `startFromOrigin` explicitly.
Put verification and remaining work in `continuationPrompt`.
Call handoff as the turn's last action because it detaches the current provider session.
Do not report completion before the continuation verifies access.

## Example

Request: "Delegate the cache fix in a separate worktree from my local commit; continue here."

Select `delegate_task` with worktree isolation.
Pass the cache-fix task and destination verification requirement.
Keep the parent binding unchanged.
Report pending until the child confirms its checkout, branch, and authorized write access.
