# ADR session-convergence-001: Analytics DB stays CLI-queried — no MCP, no ingest timer, no secondary indexes  [status: accepted]

- **Context:** The user asked for the session-analytics duckdb (historically `~/.claude/analytics/sessions.duckdb`) to become a permanent fixture for llms to query. Candidates: a read-only duckdb MCP, a systemd ingest timer, both, or the status quo plus indexing. The host livelocked 2026-07-08 on standing I/O load (see [[operations/local-llm]]), and a timed `--force` ingest measured 30 s wall, ~1 GB read / ~1.8 GB written, 2.4 GB peak RSS per full rebuild.
- **Decision:** CLI-only query surface (duckdb-expert sub-agent, `~/.duckdbrc` 8 GB cap). Lazy 1h-TTL refresh stays; no MCP server, no standing timer. The default database path is now `${XDG_CACHE_HOME:-$HOME/.cache}/dotfiles/session-analytics/sessions.duckdb`, with `SESSIONS_DB` as an explicit override. This cache path keeps shared analytics independent from any harness home.
- **Alternatives:** Read-only MCP + on-demand ingest (rejected by user — new surface not justified); MCP + systemd timer (rejected — a recurring full-rebuild ingest is exactly the standing I/O shape the box was just hardened against).
- **Superseded sub-decision (2026-07-09) — secondary indexes do NOT help on DuckDB.** The original ADR paired the CLI surface with "proper profile-derived indexes". Implementation disproved that half: `CREATE INDEX` on the analytics-pack predicates was added, then reverted after `EXPLAIN` on the live DB showed `SEQ_SCAN` for every indexed predicate. DuckDB's columnar engine does not use secondary ART indexes for base-table filter scans.
- **Consequences:** Zero new standing processes and zero secondary indexes; queries pay the ≤30 s ingest cost when TTL lapses. If the DB later needs to be genuinely always-fresh, ingest must first grow an incremental path. If pack-query latency becomes a real problem, use clustering or rollups, not `CREATE INDEX`.

_Source: session-convergence implementation session; updated 2026-09-01 for portable cache placement. Historical measurements retain their original Claude-home context._
